# V 0.9

## Release v0.9.3

Release v0.9.3 (Sep 28 2026)

**Installing this over an earlier version takes one manual step.** Volume names used to be derived from the folder you unzipped into, so installing beside an existing copy starts an empty instance and leaves your data in volumes that nothing mounts. Nothing is deleted, and the [Upgrading](https://github.com/xtreme1-io/xtreme1#upgrading) section brings it back — but do not annotate in the empty instance first. From v0.9.3 the project name is pinned, so later upgrades need no step.

### Security

1. **SSRF in `/api/data/upload`.** The URL whitelist allowed everything when empty and matched a substring of the URL when set, so any signed-in user could make the backend fetch the cloud metadata service, the database, or MinIO's admin port. Uploads now refuse non-`http(s)` schemes and hosts that resolve to internal addresses, check every redirect hop, and no longer follow a redirect at download time.

### Fixed

1. Upload failures say why they failed instead of `File url error`, and the check allows five seconds rather than one;
2. The image tool's **Close** button works in read-only mode;
3. `backend/pom.xml` shipped with the wrong version number in v0.9.2 — a release now refuses to build if any file names the wrong version;
4. Removed two point cloud shortcuts that were never bound, README claims the code does not back, and two sign-up links that answered 404.

### Changed

1. Schema changes now apply at startup through Flyway. This release contains none; the channel is what was missing;
2. Every pull request builds both images, starts the stack and runs a smoke test.

[Full release notes](https://github.com/xtreme1-io/xtreme1/releases/tag/v0.9.3)

## Release v0.9.2

Release v0.9.2 (Sep 15 2026)

A maintenance release that makes Xtreme1 installable again and ships the fixes merged since v0.9.1. There are no database schema changes.

**Upgrading from v0.9.1?** Replace `docker-compose.yml` with the one in that release. The MinIO volume path changed, and keeping the old file makes existing files unreadable.

### Installation fixes

1. `bitnami/minio:2022.9.1` was removed from Docker Hub, so fresh installs failed. MinIO now uses `bitnamilegacy/minio:2025.7.23-debian-12-r5`, with its data volume at `/bitnami/minio/data`. Existing MinIO data is read as-is;
2. The backend image is rebuilt on `eclipse-temurin:11-jre-jammy`. The previous `openjdk` base images were removed from Docker Hub, and their JDK 11.0.16 crashed on start on cgroup v2 hosts. The `JAVA_OPTS=-XX:-UseContainerSupport` workaround is no longer needed;
3. Backend and frontend images are published for `linux/amd64` and `linux/arm64`.

### Fixed

1. COCO export and import work again — the published v0.9.1 image did not contain the converter command. Bounding boxes import as rectangles, and category names survive a COCO import → export round trip;
2. The point cloud tool parses PCD files whose fields, such as intensity, are stored as integer or 64-bit values;
3. Copying objects between frames no longer carries over a stale `backId`, and saving waits for the object save to finish before releasing the lock;
4. The image tool updates the frame view again when playback stops.

### Changed

1. File URLs sent to model services are now the address you open Xtreme1 with, rather than the internal `http://minio:9000/...`, so model services running outside the Docker network can download files;
2. New optional setting `upload.url.whitelist` restricts which addresses "upload from URL" may download from.

[Full release notes](https://github.com/xtreme1-io/xtreme1/releases/tag/v0.9.2)

## Release v0.9.1

Release v0.9.1 (April 23 2024)

A few bug fixes and optimizations.

1. 2D auxiliary lines and point cloud RGB support;
2. Fixed "Request URI too large";
3. Fixed duplicated `TempDataId` when uploading a dataset;
4. Fixed the annotation status of data not changing on submit;
5. Increased the nginx body size limit to 1TB;
6. Uploading a file no longer loads all of its content into browser memory.
